## 修复：补全状态栏卡在"处理中"

- 现象：日志 `returning completion len=13 cacheHit=true` 显示补全已返回，但右下角 `ssdAgent - 处理中` 一直不消失。
- 根因：`inlineCompletionProvider.ts` 的 `provideInlineCompletionItems` 在 line 236 调用 `loading()` 把状态栏置为"处理中"后，有 4 条提前 `return []` 路径**未复位状态栏**：①`signal.aborted`/`_hasCursorMoved`（准备输入后）②`fim.debug` 调试插入路径 ③`_hasCursorMoved`（补全返回后）④`willDisplay()` 拒绝（含 `abortSignal.aborted`）。
- 修复：在 ①②③④ 的 return 前分别补 `completionStatusBar.noSuggest()`，debug 路径补 `complete()`。loading 之前的 return 路径无需复位（状态栏尚未进入 loading 态）。

## 修复：FIM 补全泄露结束标记（如 `</fim_middle>`）

- 现象：模型输出 `return a * b;\n}</fim_middle>`，编辑器/调试输出里出现 FIM 结束标记 `<fim_middle>`（starcoder/qwen preset 的 `end` 标记）及越界的 suffix `}`。
- 根因 = 模型过生成 + 停止序列缺口：小模型（deepseek-coder:1.3b 等）生成完 middle 后不靠 EOS 可靠停，继续吐 suffix 与结束标记。而 `buildStopSequences`（preprocess.ts）只加 EOS，没把 `markers.end`/`markers.hole` 加进 stop，服务器无"生成到标记即停"信号。
- 修复 1（根因）：`buildStopSequences` 加入 `getFimMarkers(config).end` 与 `.hole` 作为停止序列（stop 只匹配生成内容，不会误伤 prompt 末尾自身的标记）。
- 修复 2（防御+custom 预设）：`stripSpecialTokens`（postprocess.ts）新增可选 `markers` 参数，遇到 `markers.end` 时**截断其后全部内容**（比删除标记更彻底，顺手丢 suffix 残片），并动态把 begin/hole/end 并入剔除列表——修掉 custom 预设硬编码列表覆盖不到导致标记泄漏的隐患；`postprocessCompletion` 与 `requestFimCompletion` 透传 `getFimMarkers(config)`。
- 验证：esbuild 打包真实 `postprocess.ts`/`preprocess.ts` 跑 `fim-c-test-cases/verify_fim_marker.ts`，starcoder/qwen/deepseek/custom 四种 preset 下 `return a * b;\n}<end>` 均被规整为 `return a * b;`；干净 middle 不被误截断。注意：测试串须用 `markers.end` 自身拼接，手写 `<fim_middle>` 可能与代码字节不一致导致 indexOf=-1 假阴性。
- 文件：`src/core/costrict/auto-complete/fim/preprocess.ts`、`src/core/costrict/auto-complete/fim/postprocess.ts`、`src/core/costrict/auto-complete/fim/completionEngine.ts`。
