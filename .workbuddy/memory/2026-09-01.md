## Costrict 检查点：内置 portable Git（无需系统安装 git）

目标：消除检查点功能弹出的“检查点功能需要 Git，请安装 Git 以启用检查点”报错。环境无系统 git。

方案（方案 A，仅 Windows）：

- 把 git-for-windows 的 **PortableGit 自解压 7z 包**（`PortableGit-<ver>-64-bit.7z.exe`）放进 `src/assets/git/win32-x64/`（由用户手动下载提供，支持 Win10/Win11）。
- `src/utils/bundledGit.ts` 新增 `getBundledGitBinaryPath(extensionPath, globalStorageDir)`：首次使用时把 SFX 解压到 `globalStorage/git/portable`，解析 `cmd/git.exe` 并返回；结果缓存，并发调用共享同一次解压。
- 静默解压命令（已实测有效）：`<sfx> -y -o"<dir>"`（引号会被 7z 剥离；globalStorage 路径含空格也无碍）。
- 接线：simple-git `customBinary(gitBinaryPath)`（ShadowCheckpointService.createSanitizedGit）；`git.ts` 的 `checkGitInstalled` 对内置二进制改用 `execFile`；`core/checkpoints/index.ts` 在 `getCheckpointService` 里 await 解析路径；`extension.ts` 激活时后台 `void getBundledGitBinaryPath(...)` 预解压（不阻塞激活、失败吞掉）。
- 打包：`.vscodeignore` 加 `!assets/git/**`（与 codicons/icons 同一机制，vsce 从 `src/` 打包，运行时 `extensionPath/assets/...` 可解析）。
- `scripts/download-portable-git.mjs` 改为下载该 SFX（不再下 MinGit 并解压）。

验证：SFX 实测无声解压成功；`cmd/git.exe --version` 报 2.55.0，`git init`→`config`→`add`→`commit`→`rev-parse HEAD` 全 rc=0。`tsc -p src/tsconfig.json` 本次改动 0 报错（全项目仅 5 个预存在的 ClineProvider FIM 报错，与本任务无关）。

补完：`ShadowCheckpointService.deleteTask` 也已接内置 git（签名加 `gitBinaryPath`，`ClineProvider` 调用处 `await getBundledGitBinaryPath(this.context.extensionPath, globalStorageDir)` 传入）。至此检查点全链路（初始化/保存/恢复/diff/删除分支）均不依赖系统 git。

打包验证：沙箱内 `vsce` 因 pnpm workspace + `diff@5.2.2` 的 github 依赖卡在 `npm list --production`，无法跑；改用与 vsce 等价的 `.vscodeignore` 包含/排除模拟脚本确认 SFX 路径 `assets/git/win32-x64/PortableGit-*.7z.exe` 为 INCLUDE（控制项 README/package.json/codicons 纳入、src 下 `.ts` 排除均正确）。结论：SFX 会被打进 vsix 的 `extension/assets/git/win32-x64/`。

确定性复验：沙箱内用一个"去掉 dependencies 的最小 package.json + 真实 .vscodeignore + SFX"临时扩展目录跑通 `vsce package`（相对路径 `../node_modules/.bin/vsce` 调用，绝对路径会因 Git Bash 双盘符 `E:\e\...` 解析失败），生成的 test.vsix 内确含 `extension/assets/git/win32-x64/PortableGit-….7z.exe` [56.7MB]。打包闭环确认。

## 关键 Bug 修复（解压命令的 shell 标志）

`bundledGit.ts` 的 `extractInstaller` 原用 `execFileAsync(installer, ["-y", `-o"${extractDir}"`], {windowsHide:true})`（默认 `shell:false`）。**实测该写法在含空格路径（如 `Code - Insiders\...` 的 globalStorage、含空格用户名）下解压 EXIT=1 失败**——Node 的 Windows spawn 会把参数里的内嵌双引号重新转义成 `-o\"<dir>\"`，7-Zip 无法解析。
**修复：加 `shell:true`**（走 `cmd /c`，外壳剥离外层引号后 7-Zip 收到正确的 `-o"<dir>"`）。用含空格目录 `C:/ta dir` 对照测试：`shell:false`→FAIL，`shell:true`→git.exe 存在。本机无空格路径（如 `C:/ta`）两种都 OK，但线上必须 `shell:true`。
