## AST+LSP Prefix 扩充策略：分析 + 增加开关

### 用户本地改动（AST 跨文件上下文扩充）

- `src/core/costrict/auto-complete/types/index.ts`：PromptOptions 增加 `ast_context: string`
- `src/core/costrict/auto-complete/inlineCompletionProvider.ts`：调用 getAstContext 并塞入 promptOptions.ast_context
- 新增 `src/core/costrict/auto-complete/context/astContextProvider.ts`：解析 import → 解析到工作区文件 → tree-sitter 提取骨架定义 → 拼成上下文串（预算 2000 字符 / 5 文件 / 每文件 80ms 超时）

### 分析结论

- 核心逻辑正确（解析 import、resolveModulePath、parseSourceCodeDefinitionsForFile、预算截断、静默失败兜底）
- 发现 3 个问题：
    1. `ast_context` 为必填字段，但 `completionProvider.test.ts` 两个 promptOptions 字面量没填 → tsc 报错（已修，补 `ast_context: ""`）
    2. getAstContext 无条件调用，每次补全都触发 tree-sitter 解析 + 文件 IO（已门控）
    3. **「LSP」并未实现**——当前只有 tree-sitter AST，命名「AST+LSP」是意向性的；「扩充到 Prefix」实际在服务端（completion-agent）完成，客户端只负责计算并发送 ast_context
- 次要：parseSourceCodeDefinitionsForFile 已自带 `# filename\n` 头，astContextProvider 又加 `// From: modulePath\n`，双重头（冗余，未改）
