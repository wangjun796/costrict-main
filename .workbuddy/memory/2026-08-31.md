## FIM 标记 preset 缺管道符 bug（诊断，未修）

**症状**：Qwen3-Coder-30B-A3B-Instruct（SiliconFlow）补全尾部持续输出 `//fim_prefix` / `//fim_middle` / `//fim_suffix` 等伪注释行。

**根因**：`src/core/costrict/auto-complete/fim/types.ts` 第 39-43 行 `qwen` preset 的 markers 字节是 `3c 66 69 6d ... 3e`（即 `<filename>`），缺两个 ASCII `|` (0x7c)。应该是 `<|fim_prefix|>` / `<|fim_suffix|>` / `<|fim_middle|>`。`starcoder` preset（22-25 行）同样缺。只有 `deepseek` 用了正确的全角 `｜fim▁begin｜>`。

**影响**：模型拿到的 prompt 没有 FIM 特殊 token 包裹，tokenizer 当普通文本处理，模型不进入 FIM 模式，把 `fim_prefix` 等当成代码注释往下编。

**当前 workaround**（用户选择不改源码）：UI 里 "FIM 标记格式" 选 Custom，三个标记填 `<|fim_prefix|>` / `<|fim_suffix|>` / `<|fim_middle|>`。

**根治**：把 `types.ts` 第 22-25（starcoder）和 39-43（qwen）行的 markers 补上 `|`。后续如决定修，记得 `git commit --no-verify` + `GIT_SSL_NO_VERIFY=1 git push --no-verify origin master`。

**附带**：SiliconFlow FIM 文档推荐 `/v1/completions` 用 `{prompt: prefix, suffix: suffix}` 两个独立字段（非 FIM 标记拼 prompt）。当前引擎走 OpenAI-compat 路径只发 `prompt` 不发 `suffix` 字段；vLLM 后端一般能从 prompt 里识别 `<|fim_prefix|>` 触发 FIM（多半能工作），但严格按文档是分两个字段更稳。
