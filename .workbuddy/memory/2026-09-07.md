## 环境坑（重要，下次同步必看）

- `.husky/pre-commit` 跑 `pnpm lint`= 全量 18 包 `turbo lint`；`.husky/pre-push` 跑全量 `turbo check-types`。两者都较慢，**Bash 默认 120s 超时会被 SIGTERM 打断导致提交中止**。提交/推送命令须显式给 `timeout: 600000`。
- `git push` 走 `origin`（ghproxy.net 代理）。ghproxy 对 `info/refs` 有缓存：`git fetch` 可能把本地 `origin/master` 跟踪引用写成旧值（本次误写为 `9b20da3`，实为 `1c3f3a2`）。`git ls-remote origin master` 才是 GitHub 真实落点。
- 修正 stale 跟踪引用时 `git update-ref refs/remotes/origin/master <sha>` 会**静默失败**（因 `.git/refs/remotes/origin/` 目录不存在 + packed-refs 已有该条目）。解决办法：`mkdir -p .git/refs/remotes/origin` 后直接写 loose ref 文件，或 `git update-ref` 前先建目录。
- 直连 `github.com`（`cos`/`costrict` 远程）在本环境被网络拦截（SSL handshake / 502），只能走 ghproxy。
