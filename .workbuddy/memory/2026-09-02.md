## 修复：v1.0.3 安装后 init 报错 `fimCustomMarkerBegin is not defined`

**现象**：安装最新 vsix 后扩展卡在 "Initializing interface..."，弹窗报 `fimCustomMarkerBegin is not defined`，无法进入使用界面。

**根因**：`ClineProvider.ts` 的 `getStateToPostToWebview()` 函数（2820行）从 `buildBaseState()` 解构 FIM 变量时（2926-2942行），包含了 `fimEnabled`…`fimDebug` 等 15 个字段，但**遗漏了 `fimCustomMarkerBegin/Hole/End`**。而该函数的 return 对象（3155行）引用了这三个未解构的变量 → 运行时 ReferenceError。

注意：这三个变量在 `buildBaseState()` 内部是正确声明（3297行）和返回（3475行）的——问题纯粹是 `getStateToPostToWebview()` 的解构漏了。

**修复**：

1. 在 `getStateToPostToWebview()` 的解构列表（2942行后）补上 `fimCustomMarkerBegin, fimCustomMarkerHole, fimCustomMarkerEnd`
2. 在 `postStateToWebview()` 的 force 路径（2560行）加 try-catch：失败时记录日志并推送一个最小 fallback state，确保 webview 能退出 "Initializing interface..."
3. 在批量路径（2583行）的 catch 中改为 resolve 而非 reject（不阻塞调用方）
4. 在 `postStateToWebviewWithoutClineMessages()`（2662行）也加了 try-catch 容错

**验证**：`tsc -p src/tsconfig.json --noEmit` 零错误。

## 二次构建失败与修复（esbuild 语法错误）

首次 `pnpm vsix` 报错：`ClineProvider.ts:2675:10: Expected ")" but found "."`。

**根因**：为 `postStateToWebviewWithoutClineMessages()` 加 try-catch 时，old_string 只匹配了方法签名+前两行（到 `postMessageToWebview` 为止），而**原方法体后面还有 MDM redirect 的 `if(this.mdmService?.requiresCloudAuth()...)` 块及闭合 `}`**。新 new_string 提前用 `}` 关闭了方法，导致 MDM 块变成游离语句 + 多出一个 `}` → esbuild 在 2675 行解析失败。

**修复**：把 MDM redirect 块重新纳入方法的 try 内（与 `postMessageToWebview` 并列），方法结构恢复合法。esbuild transform API 复查 `SYNTAX OK`。

**重建**：`pnpm vsix` 成功（VSIX_EXIT=0），产物 `bin/sdd-1.0.3.vsix`（81MB），SFX 仍在 `extension/assets/git/win32-x64/PortableGit-….7z.exe`（59,454,312 B）。

**经验教训**：用 Edit 给函数体包裹 try-catch 时，old_string 必须覆盖到原函数的**完整闭合 `}`**，否则会把尾部的原有语句甩到函数外。优先匹配从签名到末尾 `}` 的整段。

## VSIX 缺 exe 排查 + git-portable 逻辑审计

**现象**：用户反映编译出的 `bin/sdd-1.0.4.vsix` 只有 21.8MB，不含 git-portable 自解压 exe（之前含 exe 的 1.0.3 是 81MB）。

**根因**：exe 文件 `src/assets/git/win32-x64/PortableGit-prerelease-2.55.0.windows.5-22--64-bit.7z.exe` 此前在 rebase/reset 操作期间从磁盘丢失（它被 `.gitignore` 第77行 `src/assets/git/` 排除，不是 git 跟踪对象，reset 不会恢复）。构建时磁盘上没有 exe → vsce 无文件可打包 → vsix 缩水到 21.8MB。用户手动还原 exe 后恢复（59,454,312 B）。

**关键结论**：

1. `.vscodeignore` 第41行 `!assets/git/**` 能**成功覆盖** `.gitignore` 的 `src/assets/git/` 排除——用 `vsce ls --no-dependencies | grep assets/git` 验证 exe 会被打包。所以 gitignore 不阻碍打包，前提是 exe 在磁盘上。
2. 构建前必须保证 exe 在磁盘上：用 `node scripts/download-portable-git.mjs`（Windows 下联网下载最新 git-for-windows 自解压版到 `src/assets/git/win32-x64/`），或手动放置。
3. 重新 `pnpm vsix` 后 `bin/sdd-1.0.4.vsix` = 81,233,777 B，包内确认有 `extension/assets/git/win32-x64/PortableGit-…-64-bit.7z.exe`。

**git-portable 逻辑完整性审计（ce5700e，全部正确）**：

- `src/utils/bundledGit.ts`：核心提取逻辑完整，`shell:true` 修复、缓存、`extractInFlight` 并发去重、`.costrict-git-extracted` marker 防重复解压均在。
- 三个调用点接线正确：`src/extension.ts:162`（启动即预解压）、`src/core/checkpoints/index.ts:119`（getCheckpointService 传给 CheckpointServiceOptions）、`src/core/webview/ClineProvider.ts:2495`（deleteTask 清理）。
- `src/services/checkpoints/ShadowCheckpointService.ts:84` `if (gitBinaryPath) git.customBinary(gitBinaryPath)` 把 bundled 路径喂给 simple-git；`src/utils/git.ts:217` `checkGitInstalled(gitBinaryPath)` 用它做 `--version` 校验；缺失时回退系统 git。
