# 嵌入式与固件安全清单

对每个类别逐项检查。标记：是（已解决）、否（必须修复后再继续）、不适用（不适用于本设备）。
与 `security-checklist.md`（覆盖应用层关注点）配合使用——本清单聚焦设备、固件与硬件层。

## 1. 安全启动与固件完整性

- [ ] 引导程序在跳转到应用镜像前校验其签名
- [ ] 每个阶段都强制签名链（信任根 -> 引导程序 -> 应用）
- [ ] 防回滚：版本/计数器校验防止降级到有漏洞的固件
- [ ] 固件镜像已签名（需要机密性时同时加密）
- [ ] 密码算法使用经过验证的库或硬件加速器，绝不自行实现
- [ ] 签名/校验密钥存放于安全元件、熔丝或 OTP，而非明文 Flash

## 2. OTA 与更新安全

- [ ] 更新载荷在安装前经过认证（签名/MAC）
- [ ] 更新包完整性（哈希）与版本均已校验
- [ ] 更新通道加密（TLS）且服务器已认证
- [ ] 失败/损坏的更新不会变砖（双分区/回滚分区）
- [ ] 更新代码与运行期密钥隔离，不可被滥用泄露密钥

## 3. 密钥与密钥存储

- [ ] 源码或固件镜像中无硬编码密钥、密码、证书或令牌
- [ ] 每设备唯一密钥（制造时注入，绝不跨设备共享）
- [ ] 密钥存放于安全元件/TPM/硬件加密/一次性熔丝，而非明文 Flash
- [ ] 密钥绝不被记录、绝不发往云端、绝不嵌入调试输出
- [ ] 密钥注入过程安全且可审计（无后门注入路径）

## 4. 调试与产测接口

- [ ] 生产固件中 JTAG/SWD/UART 调试已禁用、锁定或密码保护
- [ ] 引导回退/恢复模式不暴露未认证访问
- [ ] 工厂测试后门已移除，或以一次性注入的凭据门控
- [ ] 调试输出（UART 日志）不泄露密钥、内存内容或固件哈希

## 5. 设备通信安全

- [ ] 关键场合下设备间/总线流量（CAN、UART、SPI、I2C、射频、USB）已认证
- [ ] 安全或安全关键消息有完整性保护（MAC/签名）
- [ ] 防重放：认证消息带 nonce/序列号/时间戳
- [ ] 来自总线/网络的输入在边界处校验（长度、类型、范围、格式）
- [ ] 解析器内存安全（无无界 `memcpy`/`strcpy`，可行时做模糊测试）
- [ ] 射频/无线链路使用加密与相互认证（无固定/静态密钥）

## 6. 内存与运行时安全

- [ ] 不使用不安全的字符串/内存函数：`strcpy`、`strcat`、`sprintf`、无界 `memcpy`
- [ ] 所有缓冲区做长度检查；无越界读写
- [ ] 大小/长度/偏移计算中的整数溢出/下溢有防护
- [ ] 变量使用前已初始化（上电时 RAM 内容未定义）
- [ ] ISR 与任务共享状态受保护（volatile + 原子操作/临界区）
- [ ] ISR 非阻塞；实时路径中无动态内存分配
- [ ] 缓解栈溢出（递归有界、栈保护、MPU 栈保护）

## 7. 隔离与最小权限

- [ ] MPU/MMU 分区隔离不可信代码与数据
- [ ] 内核/虚拟化层与任务的特权级分离已强制
- [ ] 任务仅被授予所需的外设/内存
- [ ] 不可信输入处理器以最小权限运行

## 8. 物理与侧信道

- [ ] 敏感操作使用恒定时间比较（无时序侧信道）
- [ ] 开启调试熔丝/读出保护以阻碍固件提取
- [ ] 威胁模型需要时具备防篡改/篡改响应机制
- [ ] 需要时记录故障注入（毛刺攻击）考量

## 9. 日志、错误与可用性

- [ ] 错误时拒绝（失败即拒绝，而非放行）
- [ ] 记录安全相关事件（认证失败、更新尝试）且不含密钥
- [ ] 看门狗/掉电恢复防止卡死状态绕过安全
- [ ] 考虑设备上的拒绝服务向量（总线泛洪、畸形数据包）
